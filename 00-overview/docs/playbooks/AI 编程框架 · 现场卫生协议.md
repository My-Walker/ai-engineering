# AI 编程框架 · 现场卫生协议

档 C 一等协议：**用法约定，不是工具。**  
无规范包 / 无记忆 MCP / 无 setup 时，仍应按本文执行（可更慢）。

相关：[`完备集`](../concepts/AI%20编程框架%20·%20完备集.md) · [`设计准则`](../concepts/AI%20编程框架%20·%20设计准则.md)

---

## 1. 澄清结束必落盘

需求分析或澄清告一段落、即将进入实现时：

- 将**已确认**的目标、约束、验收点写入仓库文件（如 `plan.md`、结论 md、或变更规格）。  
- 或**显式声明**「小改免写」并简述理由（路径唯一、触及面小）。  
- 未落盘且未声明免写，不得当作需求已对齐。

聊天记录不作跨会话真源。

---

## 2. 非琐碎实现倾向新会话

- **倾向新开会话再实现**：需求曾长讨论、结论刚落盘、或上下文已明显变脏。  
- 新会话开场建议读取顺序：结论文件 → handoff（若有）→ 相关记忆/坑（若有）。  
- **可同会话**：小改——实现路径唯一、预估触及源文件少（经验上 ≤2）、且当前上下文仍干净。  
- 本条为**倾向**，非内核强制；上下文已糊却硬留在同会话，后果自负。

---

## 3. 阶段切换再触发流程

在澄清 → 实现 → 收工等阶段切换时，再次触发对应命令或短流程（如 `/req`、`/feat`、`/fix`），把纪律重新拉到上下文前部。  
不依赖「会话开头曾经加载过」的长 SOP。

---

## 4. 收工更新 handoff

收工或暂停时：

- 更新交接卡：做到哪、阻塞、下一步、链到结论文件（若使用记忆目录/MCP）。  
- 本任务结束则清空或标为 done，避免过期卡误导下一会话。  
- 无记忆工具时：等价物可以是仓库内短 `handoff.md` 或 issue 评论——形式随意，**必须有短交接**。

## 边界（不替代）

| 本协议不管 | 归哪里 |
| :--- | :--- |
| 未决必问 / 无证不改等硬门禁 | 执行纪律 / 规范包 |
| 坑与决策如何人审入库 | 项目记忆协议 / 记忆包 |
| 何时走 OpenSpec | 变更规格轨（档 C · D） |
| 业务仓点选安装各项 | 手装文档 → 将来交互式 setup（清单 #8） |

- [ ] 若非琐碎：是否在干净会话，且已读结论 / handoff？  
- [ ] 本阶段是否重新触发了流程命令？  
- [ ] 若暂停或结束：handoff 是否已更新或清空？
