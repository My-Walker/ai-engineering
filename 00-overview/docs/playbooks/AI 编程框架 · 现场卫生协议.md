# AI 编程框架 · 现场卫生协议

档 C 一等协议：**用法约定**；与纪律包「省心编排器」对齐。  
无规范包 / 无记忆 MCP / 无 setup 时，仍应按本文执行（可更慢）。

相关：[`完备集`](../concepts/AI%20编程框架%20·%20完备集.md) · [`设计准则`](../concepts/AI%20编程框架%20·%20设计准则.md)

---

## 1. Spec 开闸与增量

- **未开闸**：不写 `.scratch`（避免小问题也落盘）。澄清中条件到了（已确认较多、窗紧、将实现、明显非琐碎等）→ Agent **提醒开闸**；你也可主动 `/publish-spec`。  
- **已开闸**：同一 `.scratch/<feature>/spec.md`；每轮若有**新的已确认**→ Agent **自动增量更新**，不必你每次喊「更新 spec」。  
- **不写**：琐碎可明确选不写；未开闸不得假装需求已跨会话对齐。  
- 进实现/`dispatch` 前仍须无阻塞性未决（规格门）。

聊天记录不作跨切片真源。`handoff` 是进度卡，**必须链到 spec**（无则写明）。

---

## 2. 非琐碎：优先 SOP 自动 dispatch

- **默认**：非琐碎由自动 SOP 在过规格门后 **`dispatch:<skillId>`**（Task 子代理读 spec 实现），主会话 `join` 后再验证——**不必**人手 New Chat。  
- **退化**：宿主无法派子代理、或纪律包未装 dispatch 时：结论落盘后**倾向新开会话**再实现；开场读：spec → handoff（若有）→ 相关记忆/坑（若有）。  
- **可同会话 / 同窗**：琐碎——实现路径唯一、触及面小、上下文仍干净（SOP `when` 走同窗 implement/apply-fix）。

---

## 3. 阶段切换再触发流程

在澄清 → 实现 → 收工等阶段切换时，再次触发对应命令或让 Agent 按意图重路由 SOP，把纪律重新拉到上下文前部。  
不依赖「会话开头曾经加载过」的长 SOP。

---

## 4. 收工更新 handoff / runtime

收工或暂停时：

- 更新 `.scratch/<feature>/runtime.md`（若在用）与/或 handoff：做到哪、阻塞、下一步、**链到 spec**。  
- 本任务结束则清空或标为 done，避免过期卡误导下一会话。  
- 无纪律包时：等价物可以是短 `handoff.md` 或 issue 评论——形式随意，**必须有短交接且指向结论文件**。

## 边界（不替代）

| 本协议不管 | 归哪里 |
| :--- | :--- |
| 未决必问 / 无证不改等硬门禁 | 执行纪律 / 规范包 |
| 坑与决策如何人审入库 | 项目记忆协议 / 记忆包 |
| 何时走 OpenSpec | 变更规格轨（档 C · D） |
| 业务仓点选安装各项 | 手装文档 → 将来交互式 setup（清单 #8） |

---

## 自检（开干 / 收工前）

- [ ] 结论已写入 spec 或已声明琐碎免写？  
- [ ] 若非琐碎：是否走了 dispatch（或退化路径下的干净会话）且已读 spec？  
- [ ] 本阶段是否重新触发了流程 / 路由？  
- [ ] 若暂停或结束：runtime/handoff 是否已更新或清空，并链到 spec？
