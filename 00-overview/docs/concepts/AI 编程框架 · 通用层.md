# AI 编程框架 · 通用层

「标准」指的是**分层想清楚**，不是每一层都要装齐。

- **层**：缺什么补什么（功能定位，可并列）——本文唯一真源。
- **流派**：信谁多一点（权责取向）——见 [`AI 编程框架 · 四大流派与层关系.md`](./AI%20编程框架%20·%20四大流派与层关系.md)。
- **完备集**：日常装多少（厚度档）——见 [`AI 编程框架 · 完备集.md`](./AI%20编程框架%20·%20完备集.md)。
- **设计准则**：见 [`AI 编程框架 · 设计准则.md`](./AI%20编程框架%20·%20设计准则.md)。

## 1. 层一览（按流程顺序）

再加一层常被默认忽略、但所有上层都挂在其上的底座：

| 层 | 核心问题 | 缺了会怎样 | 典型代表 / 形态 |
| :--- | :--- | :--- | :--- |
| **0. 宿主能力层** | Agent 跑在哪、能调什么工具 | 上层规范无处挂载 | IDE Agent、MCP、`/` 命令、Hooks |
| **1. 规格层** | 动手前要做什么？ | 边写边改需求，返工 | OpenSpec、Spec-Kit |
| **2. 上下文层** | 此刻该看到什么？ | 长会话腐烂、约束衰减 | GSD、交接卡 / 短会话习惯、Conductor 一类 |
| **3. 执行纪律层** | 怎么干、按什么流程干？ | AI 跳步、乱跑 | skills、SOP / workflow、Superpowers |
| **4. 项目记忆层** | 长期该记住什么？ | 同类坑反复踩、决策漂移 | Trellis、项目记忆 MCP、仓库内 pitfalls/decisions |
| **5. 编排层** | 多角色如何分工？ | 单人日常通常不需要；复杂协作才缺 | BMAD、oh-my-claude、MetaGPT |
| **※ 验证与门禁** | 何时允许往下走、怎样算做完？ | 未澄清就编码、无证据就改、未检查就宣称完成 | 阶段门、人审确认、测试/lint、取证门禁 |

**验证与门禁**是必备能力，默认视为横切：条目少时可嵌在执行纪律层；压力大时再升格为独立层（见第 3 节）。

## 2. 易混的三层：规格 / 上下文 / 项目记忆

三层都常产出 Markdown，看起来都是「文档」，但用途不同：

| | 规格层 | 上下文层 | 项目记忆层 |
| :--- | :--- | :--- | :--- |
| **时间点** | 动手前 | 执行中 | 跨会话、长期 |
| **核心问题** | 要做什么？ | 此刻看到什么？ | 长期记住什么？ |
| **产物性质** | 给代理的指令 / 变更契约 | 执行编排与窗口卫生 | 仓库里的长期资产 |
| **失败模式** | 没想清楚就动手 | 长会话上下文腐烂 | 每次从零开始、决策漂移 |
| **代表** | OpenSpec、Spec-Kit | GSD、handoff 习惯 | Trellis、记忆 MCP |

一句话：**规格是「这次做什么」；上下文是「这次怎么跑才不糊」；记忆是「以后都要记得什么」。** 三者可共存，不互斥。

## 3. 验证与门禁：要有能力，不必急着拆成「第 6 层」

| | 规格层 | 执行纪律层 | 验证与门禁 |
| :--- | :--- | :--- | :--- |
| **问题** | 做成什么样 | 按什么步骤做 | 能不能进入下一步 / 算不算做完 |
| **失败模式** | 目标模糊 | 跳步、无纪律 | 该停不停、无证据放行、未验证交付 |

### 两种放法

| 放法 | 含义 | 适合 |
| :--- | :--- | :--- |
| **并进执行纪律层（推荐默认）** | 流程步骤里自带硬拦与收尾检查 | 个人 / 小团队；门禁条数少且稳定 |
| **独立成「验证与门禁层」** | 多流程共用同一套放行规则与检查清单 | 门禁散落打架、要审计「谁放行了什么」、跨工具统一确认语义 |

### 常见门禁类型

- **澄清门**：影响行为的细节未定时，不得实现、不得出实现类 Plan。
- **取证门**：修缺陷前须有复现或日志；禁止无证据猜想改代码。
- **路由门**：任务对不上流程时先问类型，不默认套最近似流程。
- **确认门**：写正式记忆、升待审、关键落盘前须人审。
- **完成门**：改完跑既有检查；未过不得宣称完成。

**结论：验证与门禁是必备能力；小体系嵌在纪律层即可，共用与审计压力变大时再升格。**

## 4. 不是五层全上：按痛点裁剪

| 主要矛盾 | 优先补的层 |
| :--- | :--- |
| AI 不按流程（答疑 / 需求 / 新功能 / 修 bug / 重构） | **执行纪律**（可嵌验证门禁） |
| 长讨论后约束变弱、越聊越糊 | **上下文**（按需重载、短会话、handoff；不一定上重型框架） |
| 坑与决策下次又忘 | **项目记忆** |
| 变更要可追溯契约（propose → apply → archive） | **规格** |
| 多角色虚拟团队协作 | **编排**（成本最高，最后考虑） |

底座 **宿主** 始终存在。日常装多少、三档厚度怎么选，见完备集文档——本文只定层谱，不定装机厚度。

---

## 5. 收束

完整框可以数出 **0～5 层**，外加一门 **验证与门禁** 能力。  
选型时先认痛点落在哪一层，再决定是否把门禁从纪律里拆出去，最后才在完备集里选厚度档。
