# 体系总纲（定稿）

> 来源：关于 SOP / skills / rules、MCP、五层与横切、目录归属的讨论定稿。  
> 本文件描述 **AI 工程体系**；不替代各层 `overview/`，也不替代具体规范包正文。

## 1. 五层划分

| 层 | 目录 | 解决什么 | 典型产物 |
|----|------|----------|----------|
| L1 模型层 | `01-model/` | 怎么「想」 | 模型选型、解码/路由、对齐基线、成本与延迟 |
| L2 能力与应用层 | `02-runtime-app/` | 人/系统怎么「用」AI | Agent 宿主、会话、权限、UX、产品模式 |
| L3 规范与编排层 | `03-spec-orchestration/` | AI「被允许怎么做」 | rules、workflows(SOP)、skills、路由、覆盖层；可多个规范包 |
| L4 工具与集成层 | `04-tools/` | AI「能碰哪些外部世界」 | MCP 及非 MCP 工具、鉴权、副作用边界 |
| L5 数据与记忆层 | `05-data-memory/` | 依据什么上下文 | 代码库、文档、RAG、会话记忆、工件 |

口诀：

**模型供智力，应用供场所，规范供契约，工具供手脚，数据供依据。**

## 2. 横切（不是第六业务层）

横切 = 同时穿过多层的治理能力，每层只落实本层「切口」。

| 横切 | 含义 | 示例切口 |
|------|------|----------|
| 安全与权限 | 各层都要管「谁能做什么、什么不能出」 | 规范门禁；应用鉴权；MCP 最小权限；记忆脱敏 |
| 观测 | 一次任务可追溯 | 命中哪条 workflow；调了哪些工具；用了哪些上下文 |
| 评测 | 变更后行为是否仍有效 | 规范包内 `evals/`；换模型/换检索时的回归 |

层解决「由什么构成」；横切解决「如何被管住、被证明有效」。  
体系级只在本总纲描述横切；具体评测实现跟被验证的产品走（例如现有规范包的 evals）。

## 3. 控制与组合关系

```text
L2 应用 ──使用──► L1 模型
L2 应用 ──使用──► L4 工具
L2 应用 ──读写──► L5 数据与记忆
L3 规范 ──约束──► L2 内 Agent 的行为（含何时调模型/工具、如何用记忆）
```

- 各层在职责、所有权、版本上 **相对独立**，可分开演进。  
- 一次真实任务中必须 **组合使用**。  
- 工具/模型进程 **不读取** 规范 Markdown；由应用内 Agent 在已加载规范约束下调用。

## 4. L3 内部概念（规范层）

| 模块 | 职责 | 不是 |
|------|------|------|
| rules | 跨任务底线 | 端到端任务步骤 |
| workflows / SOP | 一类任务的阶段化主路径；每轮至多一个主 workflow | 零散技巧清单 |
| skills | 可触发叠加的短专项手法；不替代 workflow | 主流程入口 |
| 编排 | 路由、多命中裁决、共享阶段（如 plan-shared） | 独立任务类型 |

补充：

- `plan-shared` 一类是 **workflow 共享阶段**（被动引用，非任务入口），不是 skill。  
- skills ≈ workflow 的可复用公共手法；真复用再抽，默认可写在单个 workflow 内。  
- MCP 属于 **L4 工具**，不是 L3 模块。

## 6. 目录约定

```text
ai-engineering/
├── 00-overview/                 # 本体系总纲
├── 0x-<layer>/
│   ├── overview/                # 该层总纲
│   ├── docs/                    # 该层详细文档
│   └── packages/                # 仅当该层有可发版产品时（L3 已预留）
```

- 总纲与详细文档分离：`overview/` 短而稳，`docs/` 可迭代填充。  
- **不把** 全体系总纲塞进某一个规范包仓库的发布正文。  
- 现有 `mdd-ai-eng-spec` 暂不搬迁；在 L3 `packages/` 中保留链接说明。

## 7. 学习与建设顺序（现状）

1. **L3 规范层**（已有产品 `mdd-ai-eng-spec`）— 继续做透。  
2. **L2** — 先借用 Cursor 等现成宿主，不急于自建应用仓。  
3. **L4** — 按需接 MCP/工具，并在规范约束下使用。  
4. **L5** — 记忆/检索按需建设或先借用 IDE 能力。  
5. **L1** — 模型选型与评测随效果/成本需要推进。
