# 加诊断日志

人工辅助取证。用于 `skill:diagnose-bug` 证据不足、或 SOP `when: 证据不足需人工取证`。服从 `rule:evidence-gate`。

## 进入条件

- 已有候选假设或明确「缺哪一类信号」；尚无假设时先回到 `skill:diagnose-bug` 列候选。
- 目标是拿到回传证据，不是「先修一版试试」。

## 核心规则

1. **日志 ↔ 假设**：每条探针应能区分至少两个候选（或明确否定某一个）。
2. **一次一变量**：本轮只加与当前验证相关的探针；禁止「到处 log 一遍」。
3. **可清理**：使用统一 tag（如 `[ai-discipline:diag:<短id>]`），便于事后删除。
4. **未回传停修**：人工未按约定回传前，不得继续改业务修复逻辑。
5. **脱敏**：示例输出中的密钥用占位；指导用户勿把明文密钥贴进聊天。

## 做法

1. 写明本轮要区分的假设列表。
2. 在关键路径加最少日志/计量（性能问题优先 profiler/计时，而非淹没式日志）。
3. 交付给人工：
   - 如何按**原问题路径**复现
   - 需要回传的字段（完整相关日志段、时间、环境）
   - 预期若假设成立/不成立分别长什么样
4. 收到回传后：回到 `skill:diagnose-bug`（或 SOP 诊断阶段）更新证据与排除项；再决定是否继续探针或收口原因。

## 完成标准

- 探针已加上且与假设映射清晰；人工复现与回传说明已给出；或
- 用户改用其它取证方式并留下等价证据。
- 未在等待回传期间提交「猜修」。

## 禁止

- 把临时诊断日志留作「正式修复」。
- 无假设地刷屏日志。
