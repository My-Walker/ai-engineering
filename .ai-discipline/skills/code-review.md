# 双轴代码评审

对「某固定点 → HEAD（或用户指定 tip）」的改动做只读评审。  
本 skill **不修改代码**；落地需用户确认后重路由 `sop:bugfix` / `sop:feature` 等。

## 进入条件

- 用户要求 review 分支、PR、since 某点，或 SOP/`inserts` 插入本 skill。
- 未给出基点时先问，不猜。

## 核心规则

1. **固定基点**：commit / 分支 / tag / `main` / `HEAD~n` 等；先确认可解析且 diff **非空**，否则在此失败。
2. **比较命令钉死一次**：优先三点 diff（相对 merge-base），并记下短 log；后续两轴都看同一范围。
3. **双轴分离**：Standards 与 Spec 分列；不合成单一分数。
4. **无规格不编造**：找不到 originating spec/计划/验收时，Spec 轴写「无规格可评」并跳过，不臆造需求。
5. **仓规优先**：文档化约定覆盖通用味道；工具已强制项少重复报；味道是启发式判断，不是自动违规。
6. **只读**：不改码、不自动 commit/PR。

## 做法

### 1. 钉基点

与用户确认基点 → `git rev-parse`（或等价）→ 确认 diff 非空。坏 ref 或空 diff：**失败退出**，不要空转两轴。

### 2. 找 Spec 来源（按序）

1. 用户给定路径  
2. 已确认实现计划 / 对话摘要中的验收点  
3. commit 信息中的 issue 引用（若可安全读取）  
4. `docs/` / `specs/` 等明显匹配  

皆无则询问；用户确认无规格 → Spec 轴 skip。

### 3. 找 Standards 来源

按 AGENTS 分层协议：有则 Read `.ai-discipline/docs/standards.md`，再按索引「何时读」补读命中专题（禁止 Glob `docs/`）。另可对照 `CONTRIBUTING`、周围代码与测试风格。与 gate 冲突时听 gate / AGENTS 总禁令。

### 4. Standards 轴

对照仓规 + 轻量味道启发式（短列表，不搬全书）：

| 味道 | 含义 → 方向 |
| :--- | :--- |
| 神秘命名 | 名不达意 → 改名或拆清职责 |
| 重复逻辑 | 同形逻辑多处 → 抽取共享 |
| 伸手过长 | 老用别人数据 → 行为靠近数据 |
| 原始类型丛 | 总成团的原始字段 → 考虑小类型 |
| 散弹修改 | 一逻辑改动散落多文件 → 聚合变化点 |
| 无关职责挤车 | 同 diff 多个无关理由 → 建议拆开 |

每条：位置 + 为何是问题 + 建议方向。仓规与味道冲突时听仓规。

### 5. Spec 轴（若可评）

漏实现、错实现、范围蔓延、验收缺口；引用规格/计划条目。

### 6. 输出

分节输出 Standards / Spec；条目按 Must fix / Should fix / Nice to have。  
无发现 → 明确「无发现」+ 未覆盖风险（无测、无规格、未读路径）。  
行为/规格类 Must fix：提示修复前应有红灯或复现（交回 bugfix/feature），本 skill 仍不改码。

## 完成标准

- 基点有效且范围已说明（含空 diff 失败说明）。
- 两轴均有交代（含 Spec 不可评）。
- 未在本 skill 内改业务代码。

## 禁止

- 把并行子代理当成必需机制（可同会话顺序评两轴）。
- 调用宿主 Skill tool 互调其它技能作为前提。
- 无用户授权时扩修、提交或开 PR。
- 把两轴捏成一个「总分」掩盖冲突。
