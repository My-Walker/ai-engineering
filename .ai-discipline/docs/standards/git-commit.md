# 规范专题：Git 提交说明

- **适用**：用户要求生成/撰写 commit message，或执行/协助 `git commit`（与 `standards.md` 索引「何时读」一致）
- **非目标**：不替代 gate；不自动提交；不写密钥

## 要求

1. **提交时机**：只有用户明确要求提交时才创建 commit。完成功能或修复缺陷后不得自行提交。
2. **说明语言**：commit message 使用简体中文，简洁说明这次修改的内容（侧重 why，而非堆砌文件清单）。
3. **说明格式**：`<类型>: <简短中文描述>`。
4. **类型选取**：沿用当前仓库近期提交已经使用的类型。没有先例时，在 `feat`、`fix`、`docs`、`chore` 中选最贴切的一个。
5. **提交范围**：工作区里如果同时有多组改动或未跟踪文件，不得自行决定只提交其中一部分。先列出可选项并标明推荐项，等用户选择后再执行 `git add` 和 `git commit`。可选项至少包括「全部纳入」，以及按路径分开的每一组；用户也可以自己指定范围。只有工作区里的全部改动都属于同一次提交时，才可以不询问直接提交。

## 禁止

1. 未获用户明确要求时自行 `git commit`。
2. 默认使用英文 commit message（用户明确要求英文除外）。
3. 在未确认范围时静默只 stage 部分文件。

## 示例

- `feat: 添加用户注册功能`
- `fix: 修复登录态过期未跳转`
- `docs: 补充 Git 提交说明专题`
