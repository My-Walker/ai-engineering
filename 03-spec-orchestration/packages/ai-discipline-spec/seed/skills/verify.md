# 验证结果

收工核对。不替代 `code-review`，也不在本 skill 内顺手大修。

## 进入条件

- SOP 到达验证步，或用户要求核对刚完成的改动。
- 已有明确「期望行为」或验收点（来自缺陷症状、计划或澄清结论）。

## 核心规则

1. **写出证据**：验证命令/步骤、实际结果、是否通过；无法在本环境执行的项**单独列出**，不假装已验。
2. **缺陷场景**：重跑原复现路径或原失败测试；对照原因、证据、所选修复范围是否一致。
3. **功能场景**：跑与改动相关的测试/检查；约定要全量时再全量，不默认隐瞒失败。
4. **失败处理**：验证失败 → 说明失败信号；修复需回到对应 SOP 步骤（如 `apply-fix` / `implement-change` / `diagnose-bug`），本 skill 不改成「悄悄再修一版」却无叙述。

## 做法

1. 列出本轮验收点清单。
2. 执行验证（复现脚本、测试、手动步骤说明）。
3. 汇总：通过项 / 失败项 / 跳过项（原因）。
4. 缺陷额外核对：是否仍命中原症状、是否引入明显回归（相关测试）。

## 完成标准

- 验收点均有通过、失败或「无法执行」交代。
- 读者能据此判断能否收工或须返工。

## 禁止

- 无命令/无结果的「应该没问题」。
- 把验证变成评审百科或自动提交。
