# 测试驱动

红 → 绿 → 小步整理。本 skill 产出**值得留下的行为测试**，不是测试文件行数。  
每个循环开始前与进行中都要回看本节规则，不要「写完再对照」。

## 进入条件

- 本切片要以测试驱动推进（由调用方决定是否使用本积木）。
- 影响行为或验收的**测试缝未确认**时：先澄清（服从 `rule:clarify-gate`），确认前不写测试、不写实现。

## 核心规则

1. **好测试像规格**：经公开接口描述能力（如「合法购物车可结账」）；实现可整页重写，测试仍应成立。
2. **缝（seam）= 观察行为的公共边界**：测试住在缝上，不伸进内部。
3. **缝须预约定**：列出拟测缝（各一行：测什么、抓得到/抓不到什么）→ 与用户或已确认计划对齐 → 才写第一个测试。未确认缝上禁止写测。
4. **一个竖切**：一次一个失败的能力级测试 → 最少实现让它绿 → 再整理；不为未约定行为堆测。
5. **期望值来自规格/已知样例**：禁止用与实现相同的算法在断言里重算期望（同义反复）。
6. **mock 仅系统边界**：外部 API、时钟、随机、第三方、不可控 IO；不 mock 本应属于被测单元的内部邻居。
7. **小步整理不扩需求**：重构不得夹带新行为。

## 做法

1. **对齐用词（可选）**：若仓内有 glossary/相关 ADR，可 Read；不在此新建记忆资产。若接口形状本身成问题，用选项+推荐与人对齐，勿空想一打缝。
2. **提出 seams**：每个缝注明能抓住的回归与故意不覆盖的部分；影响验收则问人确认。
3. **红**：写一个失败测试并真实跑红；记录命令与失败信号。红不起来就先修测试或缝，不要假装进入绿。
4. **绿**：最少实现；再跑同一命令确认绿。
5. **整理**：命名、重复、结构；保持绿；范围外改动不做。
6. **下一竖切**或交回调用方 / SOP。

### 缺陷修复时的 TDD

若本切片是修已确认缺陷：红灯测试应断言**用户症状**（或最小复现），修好后该测试保持为回归。无缝/无环境可跑测时，在完成标准中写明，并依赖 `skill:verify` 的复现命令。

## 完成标准

- 至少一个与本切片相关的红→绿循环已真实跑过；或用户确认本环境无法跑测并写明替代验证。
- 所用缝均在确认列表内；未引入未约定行为的横向测试堆。

## 反模式

- **implementation-coupled**：mock 内部协作、测 private、经旁路（直接查库等）断言本应由接口表达的行为。
- **tautological**：断言重算实现同一公式。
- **horizontal slicing**：先写一堆想象中的测试再实现，或一次铺开多层未确认行为。
- **测试通过但规格谎言**：绿测覆盖的是错缝，用户症状仍红。
