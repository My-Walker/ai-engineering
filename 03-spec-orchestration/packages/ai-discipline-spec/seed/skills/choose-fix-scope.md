# 选择修复范围

缺陷修复的范围门。定因之后、改码之前。

## 进入条件

- `diagnose-bug` 已给出**已确认原因 + 证据**（或等价回传证据已分析完毕）。
- 尚未开始按猜想改修复代码。

## 核心规则

1. **先停改码**：进入本 skill 后、用户选定前，不得开始修复实现。
2. **必须二选一或自定义**：最小修复 vs 长期维护修复；允许用户自定义第三方案，但仍须书面选定。
3. **给推荐**：影响面只在一处 → 偏最小；同类路径会复发/债务高 → 偏长期维护；写清依据。
4. **长期维护仍锚定已确认原因**：不是借口无范围大重构。

## 做法

1. 用三五行重申原因与证据指针。
2. 给出方案对比（改动面、风险、回归价值）+ 推荐。
3. 等待用户明确选定。
4. 若选长期且改动面大：交 SOP optional `write-impl-plan`；否则进入 `tdd?` / `apply-fix`。

## 完成标准

- 用户已选定范围（或等价书面确认）；选定记录可被后续 `apply-fix` 引用。
- 选定前无修复写码。

## 禁止

- Agent 自行假定「当然最小」并开改。
- 把「长期维护」写成无边界翻写。
