# 拷问澄清

事前对齐需求/计划，消除**会影响行为或验收**的歧义。服从 `rule:clarify-gate`。  
本层**不**负责把结论写成项目 glossary/ADR 真源；若仓内已有，可 Read 以对齐用词。

## 进入条件

- 需要对齐会影响行为或验收的决策（由调用方决定是否使用本积木）。
- 已能复述任务目标；否则先用一句话确认目标再拷问。

## 核心规则

1. **事实自读、决策问人**：能靠读代码/配置/文档回答的，先读再问；只把真正的取舍交给用户。
2. **frontier（前沿）**：只问**当前阻塞前进**且**此刻已可回答**的决策枝；不要把三个月后的细节一次倒完。
3. **一轮问透可答枝**：同一轮把已解锁的问题问完，减少来回空转；用户答完再开下一层前沿。
4. **选项 + 推荐**：每题给可选项并标明推荐项及一句理由；禁止「跳过未决继续实现」伪选项。
5. **共享理解**：阶段性把已确认结论短列表回显，避免重复追问。
6. **硬停**：仍有影响行为/验收（含测试缝）的未决时，不写业务代码、不写业务测试、不输出实现计划正文。

## 做法

1. **复述目标与约束**；相关则 Read 已有 glossary/ADR/周边代码。
2. **画出开放枝**（只列相关）：产品行为、边界与错误处理、兼容、权限、性能预算、数据迁移、**测试缝/验收方式**等。
3. **本轮提问**：对每个可答枝 → 背景一句 → 选项 → 推荐；批量给出，等人一次答复。
4. **更新已确认表**；关闭枝或标记「范围外/已知风险」（须用户书面接受且不影响本切片验收）。
5. **重复**直到无阻塞未决，或用户明确暂停澄清。
6. **回交** SOP 下一步；交付「已确认结论」短表（含已定测试缝，若有）。

## 完成标准

- 影响本切片行为/验收的未决已关闭，或已书面标为范围外；且
- 已确认结论已回显；未在未决未清时写实现、业务测试或实现类 Plan 正文。

## 反模式

- 能读代码却反复问「这个函数干什么」。
- 一次抛出二十个不相干未来问题。
- 无选项的开放题导致无法决策。
- 用户说「你看着办」时把未决假装已决并开始写码。
- 把澄清变成撰写 ADR/glossary 的作者任务（那是记忆/文档轨，不是本 skill）。
