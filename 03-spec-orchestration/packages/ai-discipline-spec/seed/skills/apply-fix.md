# 应用修复

**仅**用于缺陷修复实施（`sop:bugfix`）。功能新增走 `implement-change`。

## 进入条件

- `diagnose-bug` 已有「已确认原因 + 证据」；且
- `choose-fix-scope` 用户已选定范围（及可选计划已确认或合法跳过）；且
- `rule:evidence-gate` 已放行。

## 核心规则

1. **只修已确认原因**：不扩未选定的重构，不引入无证据的第二处「顺手修」。
2. **行为/规格类缺陷**：若尚无覆盖该症状的回归测试，优先先红灯再改（可与 optional `tdd` 衔接）；有环则改完必须复跑。
3. **范围**：最小修复 = 直接相关代码；长期维护 = 仅限用户已选同类路径，仍不得借机大翻车。
4. **不自动 commit / PR**。

## 做法

1. 重申：原因、证据指针、选定范围、计划要点（若有）。
2. 按范围改代码；保持项目风格。
3. 跑原复现命令/失败测试及直接相关检查。
4. 交回 SOP 的 `verify`（本 skill 不替代验证叙事）。

## 完成标准

- 改动落在选定范围内；原反馈环或复现路径已再跑（或写明本环境无法跑及原因）。
- 无范围外大改、无第二处无证据修复。

## 禁止

- 无证据「优化」邻近模块。
- 把 review 里未授权的味道清理塞进本次缺陷修复。
