# 分析取证阅读

只读取证。服从 `rule:explore-readonly`。

## 进入条件

- `explore-scope` 已定范围（或等价确认）。
- 需要基于仓库事实作答，而非仅凭用户短描述。

## 核心规则

1. **禁止空口下结论**：用工具阅读相关源码、测试与必要文档。
2. **区分已证实 vs 推断**：推断必须标明依据不足。
3. **能读就不问事实**：实现细节、现有行为以代码为准；只把产品取舍问人。
4. **优先一手材料**：源码/测试 > 过时评论；外部二手资料须标注。
5. **不改业务代码**；不派「必须后台子代理」作为本 skill 前提。

## 做法

1. 按范围列出待读路径与问题清单。
2. 阅读并记录：机制如何工作、关键约束、已有测试覆盖缺口。
3. 整理证据表：主张 → 证实/推断 → 指针（文件路径）。
4. 交给 `explore-report` 组织输出。

## 完成标准

- 关键主张有路径级依据或明确标为推断。
- 本阶段无业务写码。
