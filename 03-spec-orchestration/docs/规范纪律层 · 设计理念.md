# 规范纪律层 · 设计理念

本文是 **L3（`03-spec-orchestration`）本层** 设计定稿。  
跨层层谱 / 完备集 / 框架准则见 [`00-overview/docs/`](../../00-overview/docs/)。

阅读顺序：定位 → 理念 → … → 宿主 command 登记 → 元 skill / 校验 / sync → 包内目录树。

---

## 1. 定位

**主责（本层拥有）：** 怎么干、按什么流程干、何时允许往下走（执行纪律；门禁能力嵌在本层）。

**可触碰（不拥有真源）：** 规格、上下文卫生、项目记忆、编排、宿主——**可以**用可选 skills / 挂载约定去碰，但对应层的契约正文、记忆库、会话 OS、多角色体系、IDE 本身仍归各层；本层不替代其协议与真源。

**默认少碰：** 多角色编排、自建宿主。

与通用层一致：门禁是必备能力，默认嵌在执行纪律层。

---

## 2. 设计理念

1. **完整纪律模型**：薄常驻（总禁令 + 指向 SOP 索引）+（路由 → SOP）+ 原子 skills + 少量 skill commands。  
2. **Skill 原子化**：一个 skill = **单一任务 + 具体做法**；可被人组合，高频者用 **command** 主动触发。参考 [mattpocock/skills](https://github.com/mattpocock/skills) 的积木化、人控、可组合——**不**照搬其「装进宿主 skills 目录」为运行面。  
3. **SOP 是组合，不是百科**：只装配原子 skills + 门禁 + 分支 + 完成定义；**禁止**把整单做法写成一个大 skill / 大 md 冒充「更先进」。  
4. **省心 + 灵活**：路由认意图进 SOP；中途人可用 skill **command** 插入原子积木，再回主路径。  
5. **真源自有格式**：skills / rules / SOP 正文放仓内人类可见目录，格式由本层/规范包约定，**不必**迁就宿主 skills·rules 文件布局。  
6. **暴露面极窄**：Agent 常驻只见薄壳；完整纪律随 SOP 步骤加载；command 给人用，不进常驻菜单。  
7. **常驻宜薄**：长文不整本常驻；权威在自有文件。  
8. **宿主只做薄适配**：写薄 `AGENTS.md`（Claude 镜像 `CLAUDE.md`）+ **差异注册少量 skill commands**；不把整库 skills/rules 翻译进宿主发现路径。  
9. **可自我调整**：必备元 skill + **一条** command，辅助增删改 rules / skills / SOP /（skill）command 声明；不局限于预制件。  
10. **存储**：真源集中在项目级点目录 `.ai-discipline/`（工具资产，与业务文件分离）；薄 `AGENTS.md` 留仓根供宿主发现。用户级仅当产品明确支持时可选。

```text
执行纪律 ≈ 薄常驻（AGENTS：总禁令 + 加载协议 + 索引指针）
         +（Read workflows/index → SOP 组合菜谱）
         + 原子 skills（`.ai-discipline/skills/`；高频用 command 触发）
```

用法示意（修缺陷）：

```text
意图 bugfix ──薄常驻索引/路由──► 读并跟随 SOP（无 SOP command）
  默认步骤：引用原子 skills + 阶段门禁（Read 自有文件）
  分析反复不行 → 人触发 skill command：add-logs → 回传 → 再 analyze
  薄常驻总闸 + 随 SOP 加载的取证门 拦「无证据改代码」
```

## 3. 元素组成与关系

| 元素 | 一句话 |
| :--- | :--- |
| **门禁** | 作用：能不能进下一步 / 算不算做完（否决型）。 |
| **rules** | 载体：**约束资产**（`.ai-discipline/rules/`）。`role: gate`（否决型）与 `role: convention`（合规提醒型）；无独立 `gate`/`convention` 的 `kind`。长规范/坑案例见 **docs 项目知识库**（§4.2.1），不是 rule。 |
| **路由** | 意图分诊 → 选定 SOP；依据 **`workflows/index.md`**；对不上走 **`ask-route`**（见 §7）。 |
| **SOP** | 任务级**组合菜谱**；目录 **`.ai-discipline/workflows/`**（仅项目）。**暂不**注册 command。 |
| **skill** | **原子做法积木**；真源在 `.ai-discipline/skills/`（HOW，不是规范百科）。 |
| **command** | 宿主侧薄入口；**只用于触发 skill**（非常用可不注册）。 |
| **元 skill（作者态）** | 辅助增删改 rules / skills / SOP / command 声明；占 **1** 条 skill command。 |
| **完成定义** | 收工条款；写在 SOP 内，非独立资产类型。 |

**关系：**

```text
薄常驻 AGENTS ──暴露──► 总禁令 + 加载协议 + 指向 workflows/index（索引不进 AGENTS）
路由 ──Read index──► SOP（组合；再按 steps Read skill/rule；无 SOP command）
                 ├─引用──► 原子 skills（步骤内 Read；或走已注册 command）
                 ├─引用──► rules：`gate`（否决）与可选 `convention`（合规提醒）
                 ├─允许──► 人工插入（skill command）后回到主路径
                 └─附带──► 完成定义
元 skill command ──作者态──► 增删改真源；而后 CLI validate/sync/install（M1）
人也可不经 SOP，用 skill command / 直读 skill 自拼（薄常驻总禁令仍在）
```

组装键：稳定 **`id`**；引用写 **`类型 + id`**（`rule` / `skill` / `sop`）。**不设 `gate` / `convention` 作为 `kind`。**  
**Command 不对应 `sop`。** SOP 与 skill 不得糊成一种。

## 4. 各元素详解

### 4.1 门禁（`role: gate`）

**作用：** **否决型**放行/完成判断——未满足 → 不得进入下一步 / 不得宣称完成。常见：澄清门、取证门、完成门、路由门；以及「提交信息必须…」「测试必须落在 `__tests__/`」等硬必须。  
实现载体是 rules（`role: gate`），不是第三种资产。

### 4.2 rules（约束资产）

约束的**可引用**资产类型（短文、稳定 `id`）。真源在 **`.ai-discipline/rules/`**（YAML frontmatter + Markdown），**不**以写入宿主 `.cursor/rules` 等为默认运行面。  
对人称呼用**约束资产**；勿把本目录当成 Cursor/旧包那种「通用规范百科」（长文规范在 docs）。

| 字段 | 取值 | 含义 |
| :--- | :--- | :--- |
| `role` | `gate` \| `convention` | **语义角色**（否决 vs 合规提醒），**不是**强制力等级——本层 gate/convention/docs 均为软约束 |
| `always` | `true` \| `false` | 是否进入**薄常驻摘要**（不是「整文件 always 进宿主 rules」） |

| `role` | 定义 | `always` / 引用 |
| :--- | :--- | :--- |
| **`gate`** | 否决型：放行或完成判断 | 关键者 `always: true` 进 AGENTS 总禁令；亦可仅挂 SOP `steps` |
| **`convention`** | **合规提醒型**短约束：应遵守的写法/边界；**不**把「阶段放行」绑在这条上 | **默认可挂 `steps` / 被 skill 点名**；`always` 默认 `false`，仅极少数全局短条可进总禁令；**少用、可空**（空 ≠ 并进 docs） |

**选型（作者）：**

```text
一步怎么做、可复用                 → skill（做法积木）
未满足 → 禁止往下 / 不算完成       → gate
短、要 rule:id、合规提醒非否决     → convention（少用；默认 always: false）
长文、案例、勤增删的规范/坑       → docs（§4.2.1）；硬条再晋升为 gate/convention
```

宿主**原生不能**区分 `gate` / `convention`；分类给人与作者工具。Agent 不按 `role` 分支，只见 always 的 `summary`，以及被点名 Read 到的正文。  
**薄 AGENTS 不解释** role 分类（避免占常驻预算、避免「软/硬」误解）。

### 4.2.1 项目知识库 docs（与 convention 区分）

约定路径：`.ai-discipline/docs/`。对人称呼用**项目知识库**（KNOW）。

| 路径 | 作用 |
| :--- | :--- |
| `standards.md` / `pitfalls.md` | **薄入口**：全局总则/全局坑 + **专题索引表**（路径 / 何时读 / 一句话） |
| `standards/` / `pitfalls/` | 专题/分册正文；按索引「何时读」**按需** Read |
| `*/_template.md` | 新建专题时的骨架 |

**不是** rule：无 `kind`/`id`，**不能**写入 SOP `steps` 的 `use: rule:…`。  
**加载（AGENTS 强制加载）：** 入口文件分别「有则 Read、缺则跳过该文件」；专题仅索引命中时再读；**禁止** Glob `docs/`。  
与 gate/convention：硬条**晋升**为 rule；docs 可链 `rule:id`。  
install 将 `docs/` 与 skills 同策略补缺；`--force` 覆盖同名文件。写码/修复/评审 skill 应再次按该分层协议补读。

**常见误读：** `docs/standards/*`（如 git-commit）等内容**长得像**旧式跨任务「通用 rule」，且与 `skills/`、`rules/` 同级并列，易被当成第三套规范百科。协议上它们是知识库：按「何时读」加载，**不可**进 SOP 组装键；真要否决或短条可引用，再晋升为 rule。`convention` 也不应因「种子暂无」而并进 docs——可引用性是它与 docs 的分界。

### 4.3 路由

根据用户意图，对照 **`.ai-discipline/workflows/index.md`** 选定 SOP（如缺陷 → `sop:bugfix`）。认 SOP，不把原子 skill / skill command 当任务主入口。  
无命中、多命中难决或意图混杂 → 完整 Read **`skill:ask-route`**，按该 skill 列出选项并等人选定，再加载对应 SOP。意图变更可重路由。

### 4.4 SOP（目录：`.ai-discipline/workflows/`）

**SOP = 组合，不是做法全书。** 格式由规范包约定（推荐 YAML frontmatter + Markdown）。仅项目级。  
**SOP 先不注册 command**；进入方式 = 索引/路由 → Read 并跟随该文件。

#### SOP 组成积木

| 积木 | 必要 | 作用 |
| :--- | :--- | :--- |
| **适用 / 路由声明** | 必备 | `triggers`（+ 可选 `priority`）；汇总进 **`workflows/index.md`** |
| **步骤序列** | 必备 | frontmatter **`steps:`**（§8）；`skill:` / `rule:` 引用；禁止内联大段做法 |
| **阶段门禁** | 必备 | `steps` 中的 `rule:`（否决型须 `role: gate`；合规提醒可用 `convention`，不替代完成/放行闸） |
| **完成定义** | 必备 | 写在本文件正文；由完成门对照 |
| **分支 / HITL** | 常用 | `steps[]` 修饰链（`when` / `confirm` 等算子，语义见 §8.4） |
| **人工插入点** | 建议写明 | `inserts`；人用 **skill command**（或直读 skill）中途插入，**不视为离开 SOP** |
| **失败回退 / 重路由** | 可选 | 写在 SOP 正文；门不过或意图变了怎么办 |
| **产出指针** | 可选 | 结论 / handoff 等落点提示 |

**两种开车方式（同时支持）：**

| 模式 | 行为 |
| :--- | :--- |
| **默认（省心）** | 路由 → SOP → 按组合加载原子 skills、过门禁 |
| **介入（灵活）** | 人中途打 **skill command**，再续 SOP |
| **纯手搓** | 不进 SOP，人用 skill command / 直读 skill 自拼；薄常驻总禁令仍生效 |

#### 与流程图概念的对应

SOP 就是一张任务流程图；积木对应节点/边，不是另一套模型。默认不做并行网关；子流程慎用。

| 流程图概念 | 本层对应 |
| :--- | :--- |
| 流程 / Graph | 一条 SOP（`.ai-discipline/workflows/` 中一带 `id` 的文件） |
| 开始 Start | 路由命中本 SOP（索引 + 适用声明） |
| 结束 End | 完成定义 + 完成门放行 |
| 动作节点 Action / Task | **原子 skill 引用** |
| 条件 / 判断 Decision | **阶段门禁**（`rule` + `role: gate`） |
| 分支 Branch | **HITL / 失败分支**（含回流） |
| 顺序流 Sequence Flow | **步骤序列**的先后 |
| 等待 Wait | 等人回传证据；或停在门禁直至条件满足 |
| 人工节点 Manual | **人工插入点**（skill command / 直读 skill 后回到当前阶段） |
| 子流程 Subprocess | 默认不做；真要复用整段再引用另一条 SOP（慎用） |
| 并行 Parallel | 默认不做（保持简单） |

### 4.5 skill（做法积木）

**原子化：** 单一任务 + 具体做法（分析 / 加日志 / 修复 / 验证等宜拆开）。真源在 `.ai-discipline/skills/`，格式自定。对人称呼用**做法积木**（HOW）；不是项目规范百科，也不是任务主入口。

- **进不进入由 SOP/调用方决定**（修饰链 → 是否 `use`）；skill **不**复述 `when`/`confirm` 编排。  
- skill「进入条件」只写**做法前置**（做对这件事需要什么已成立），不写「何时被调度」。  
- SOP 步骤：**点名 id**，Agent 按路径约定 **`Read`** 对应文件（主路径不走 command）。  
- **不**默认安装进宿主 skills 发现目录（command 清单内的 Codex 例外见 §10）。  
- 只在一处用、尚未复用的步骤可暂内联在 SOP，真复用再抽成 skill。

### 4.6 command（仅 skill）

宿主侧**薄注册**，用于**主动触发 skill**，不是 SOP 入口。

| 约定 | 定稿 |
| :--- | :--- |
| 触发对象 | **仅 skill** |
| SOP | **先不挂 command**（元 skill 可**编辑** SOP 文件，但不把 SOP 登记为 command） |
| 数量 | 只注册常用重要 skill；典型 **5～6**，上限约 **10**（**含**下方元 skill 那 1 条） |
| 载荷 | 薄壳：指向 skill 文件 / id + 必要前言；不把百科贴进 command 定义 |
| 宿主差异 | 安装时按所选宿主登记 slash/自定义命令等；**只写所选宿主** |

未注册的 skill 仍可通过 SOP 引用或人 `@` / Read 使用。

### 4.7 元 skill：纪律资产作者（定稿）

**定位：** 作者态 / 维护态，不是修 bug 等业务 SOP 的主路径。  
**形态：** **一个**原子 skill（如 `discipline-author`）+ **一条** skill command 指向它。  
**不为** rule / sop /「每种操作」各挂 command。

| 能力 | 说明 |
| :--- | :--- |
| 对象 | `rule` / `skill` / `sop` / **skill command 声明**（挂载或取消挂载） |
| 操作 | 增、删、改（含重命名 id 时的引用检修） |
| 约束 | 遵守本层组合纪律：SOP 步骤只引用 skill id；不把整单写成大 skill；command 仅 skill且总数 ≤10 |
| 收尾 | 写真源后走 CLI：**validate → sync**；若改了 command 再 **install** 登记宿主（见 §11，**M1**） |
| 确认 | **默认先给出变更摘要，经人确认再写盘**；禁止在业务 SOP 执行中「顺手」改纪律真源 |

薄常驻总禁令应写明：改 rules/skills/SOP/command **只允许经本元 command**（或人直接改文件），避免执行会话污染真源。细则见 **§11**。

### 4.8 完成定义

写在对应 SOP 内；由完成门（rule）对照放行。不设独立 `dod` 类型。

## 5. 调度权与触发（定稿）

调度权靠**暴露面设计**，不靠「把 skills 装进宿主再关自调用」当主方案。

| 零件 | 如何进入会话 | 谁触发 |
| :--- | :--- | :--- |
| **薄常驻** | `AGENTS.md`（Claude：`CLAUDE.md` 镜像） | 每会话默认在 |
| **SOP** | Read **`workflows/index.md`** 匹配 → Read 对应 SOP | Agent 识意图，或人点名路径；**无 command** |
| **原子 skill** | SOP 步骤 Read；或 **skill command**；或人直读 | 禁止依赖宿主 skill 自选；**无** skills 路由索引 |
| **阶段门禁 / 长 rule** | 随 SOP `steps` 加载 | **无** rules 路由索引；always 摘要进 AGENTS |
| **中途介入** | **skill command（人触发）** | 人点宿主 command；Agent 主路径用 Read，不靠常驻菜单自调 |
| **纪律资产作者** | 元 skill **command** | **人**显式进入作者态；确认后写盘 |

薄常驻（`AGENTS.md`）只含：

1. **总禁令**（短；来自 `always: true` 的 `summary`）；  
2. **强制加载协议** + **SOP 索引指针**（索引大表不进 AGENTS）；  
3. **路由不明菜单**（固定几行）。

**不**把 command 清单/指针塞进 AGENTS：省 token、减少 Agent 主动抢 command 方向盘。  
`commands/index.yaml` 仅服务安装登记；人从宿主 `/` 菜单使用。

**唯一路由索引文件：** `.ai-discipline/workflows/index.md`（由各 SOP 的 `id`/`name`/`triggers` sync 生成）。  
不要求、不暴露 `rules/index.md` / `skills/index.md` 作为 Agent 路由面。

**直读路径约定（禁止靠扫描发现）：**

```text
.ai-discipline/workflows/{id}.md   # 另：workflows/index.md 仅 SOP 路由
.ai-discipline/skills/{id}.md
.ai-discipline/rules/{id}.md
```

SOP `steps` 已点名 `skill:id` / `rule:id` → Agent 按上式拼路径 `Read`，**不必**也不应 Glob 目录找文件。同 id 禁止多文件。  
**正文可执行引用**（回到/转交/服从/重路由某资产）亦写 `skill|rule|sop:id`，与 steps 同形；纯中文叙述可保留。需要立刻 Read 时可并用 `.ai-discipline/.../{id}.md`。

**诚实上限 / 本层不提供硬拦：**  
门禁与 SOP 均为**提示性纪律**（软约束）。本层**不**拦截编辑器工具、**不**做提交/CI 硬闸、**不**提供会话内步骤状态机。模型仍可能跳过 Read 直接改代码；保险靠：薄 AGENTS +（Cursor）极薄 always 锚点 + 人工审查；长 SOP 断点靠人触发 **`handoff`**，当前**不做**状态文件。  
若将来某条 SOP 也要 command，须单独立项，**不得**默认同化「command = SOP」。

## 6. 落盘与宿主适配（定稿）

**产品（命名 N2）：**

| 项 | 值 |
| :--- | :--- |
| 包目录 | `03-spec-orchestration/packages/ai-discipline-spec/` |
| npm | `@ai-engineering/discipline` |
| CLI | `discipline` |
| 锚点 id | `ai-discipline` |

**不动**既有 `mdd-ai-eng-spec`。  
**宿主：** 命令可传参；**未指定则交互多选**（Cursor / Claude Code / Codex）；**只写入所选宿主的薄适配**。  
**范围：** 默认项目。  
**真源格式：** 由规范包自定（推荐 YAML frontmatter + Markdown）；**运行不要求**译成宿主 skills/rules 树。

## 8. 资产 schema / frontmatter（定稿）

**格式：** 每个 `sop` / `skill` / `rule` 一份 `*.md` = YAML frontmatter + 中文 Markdown 正文。  
**command：** 不设 md 类型；见 `.ai-discipline/commands/index.yaml`（**C1**）。  
**SOP 步骤：** 结构化写在 frontmatter `steps:`（**S1**），正文不写做法百科。

### 8.1 共用

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `kind` | ✅ | `sop` \| `skill` \| `rule`（与目录一致；供元 skill 校验） |
| `id` | ✅ | 短横线英文，**无类型前缀**（如 `bugfix`、`clarify-grill`）；文件名必须与 id 一致 |
| `name` | ✅ | 中文展示名 |
| `description` | ✅ | 一句话 |

**引用写法：** `kind:id`（如 `skill:diagnose-bug`、`rule:evidence-gate`、`sop:bugfix`）。  
**落盘：** `.ai-discipline/workflows|skills|rules/{id}.md`（`commands/index.yaml` 除外）。按 id 直读，无 skills/rules 路由索引，禁止扫描发现。  
不设 `gate` / `dod` / `command` 作为 `kind`。

### 8.2 `rule`

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `role` | ✅ | `gate`（否决型）\| `convention`（合规提醒型）；差别见 §4.2，非强制力等级 |
| `always` | ✅ | `true` \| `false`；`true` → 要点进薄 AGENTS。convention **默认建议 `false`** |
| `summary` | `always: true` 时必填 | 一行中文，供常驻摘要 |

```yaml
---
kind: rule
id: evidence-gate
name: 取证门
description: 无复现或日志证据时禁止改缺陷代码
role: gate
always: true
summary: 无复现/日志证据不得改缺陷代码
---
```

```yaml
---
kind: rule
id: log-tag-prefix
name: 诊断日志前缀
description: 临时诊断日志须带统一 tag 前缀
role: convention
always: false
---
```

### 8.3 `skill`

无额外必填宿主字段；是否挂 command **只**由 `commands/index.yaml` 决定（避免双源）。

```yaml
---
kind: skill
id: clarify-grill
name: 拷问澄清
description: 对人连环追问直到计划无歧义
---
```

正文写单一任务做法。

### 8.4 `sop`（薄；步骤在 frontmatter）

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `triggers` | ✅ | 字符串列表；汇总进 **`workflows/index.md`** |
| `priority` | 建议 | 整数；越大越优先；多命中时先比 priority，并列再问人（进 index） |
| `steps` | ✅ | 有序数组；元素见下 |
| `inserts` | 建议 | 允许中途插入的 `skill:…` 列表 |

**`steps[]` 元素：**

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `use` | ✅ | `skill:id` 或 `rule:id` |
| `when` | 否 | 人话条件（见下方执行语义） |
| `confirm` | 否 | 默认 `false`；为 `true` 时到站须人选是否执行 `use` |

**step 修饰链执行语义（禁止自猜）：**

**总原则：** 每个 `steps[]` 项以 `use` 为动作；`use` 以外的字段构成**修饰链**。按**固定算子顺序**跑完修饰链，用**最终结果**决定是否执行 `use`。链未决（例如 `confirm` 尚未人选）→ **不得**执行该 `use`，也不得进入后续写码类步骤。SOP 正文不复述本表，只引用 AGENTS/本条。

**固定算子顺序（与 YAML 键书写顺序无关）：** `when`（若有）→ `confirm`（若有）→ 是否 `use`。

| 算子 / 组合 | 语义 |
| :--- | :--- |
| **`when`** | 写入条件判断（及可供推荐的结论）。**不因判断为假而短路掉后续 `confirm`** |
| **`confirm: true`** | 到站 HITL：选项+推荐（有上游 `when` 则推荐跟判断，否则通常推荐跳过）；人选为是否 `use` 的**最终决定**；禁止静默跳过 |
| **仅 `when`（无 confirm）** | 判断结果**直接**决定是否 `use`（硬闸：假→跳过，真→必须 `use`） |
| **仅 `confirm`（无 when）** | 人选决定是否 `use` |
| **`when` + `confirm`** | 先 `when`，再**无论真假**都 `confirm`；人选决定是否 `use` |
| **二者皆无** | **必须**执行 `use` |
| **`use: rule:…`** | 必须完整 Read 该 rule，并按条文**停止或放行**；Read 不等于自动「已过门」——不满足则不得进入后续写码类步骤 |
| **`steps` 数组顺序** | 严格按数组先后；跳过不等于删除后续依赖，若后续步依赖被跳过步的产出，应停问用户 |
| **侧门** | 主路径不配「静默可跳」步；人随时插入用 `inserts` + skill command |

```yaml
---
kind: sop
id: bugfix
name: 缺陷修复
description: 缺陷/报错的主路径
triggers: [缺陷, bug, 报错]
priority: 100
steps:
  - use: skill:clarify-grill
    confirm: true
  - use: skill:diagnose-bug
  - use: rule:evidence-gate
  - use: skill:add-logs
    when: 证据不足需人工取证
  - use: skill:choose-fix-scope
  - use: skill:write-impl-plan
    when: 长期维护或改动面大
    confirm: true
  - use: skill:tdd
    confirm: true
  - use: skill:apply-fix
  - use: skill:verify
  - use: rule:bugfix-complete
inserts:
  - skill:add-logs
  - skill:clarify-grill
  - skill:verify
  - skill:code-review
  - skill:handoff
---
```

正文：完成定义、分支/HITL 说明等；**禁止**内联整段 skill 做法。

### 10.1 登记表

| :--- | :--- | :--- | :--- | :--- |
| **Cursor** | **H1** | `.cursor/commands/{id}.md`；另写极薄 always **`ai-discipline.mdc`**（只逼读 AGENTS） | `/` + id | 人选才注入 command；锚点不可代替 AGENTS |
| **Claude Code** | 同 commands 目录 | `.claude/commands/{id}.md` + **`CLAUDE.md`**（常驻；不加额外 rules always） | `/` + id | frontmatter：`disable-model-invocation: true` |
| **Codex** | **X1**（best-effort） | `.agents/skills/{id}/SKILL.md`；常驻靠仓根 **AGENTS.md**（不加额外 always） | `$id` / 技能面板显式选 | **禁止隐式调用**（字段以安装时 Codex 文档为准） |

说明：Codex 已废弃 `~/.codex/prompts` 自定义 slash；**仅 command 清单内**的 skill 允许装成「关隐式」的 host skill，**不**等于整库进宿主 skills。常驻通道总表见 §6。

未选中的宿主：不写任何 command 薄壳。

### 10.2 薄壳载荷（各宿主同义）

禁止把 skill 全文复制进薄壳。固定三步：

1. 完整 Read `.ai-discipline/skills/{id}.md`  
2. 严格按该文件执行  
3. 完成后回到用户当前任务；若在 SOP 中途，回到该阶段，勿另起无关主路径  

**Cursor 示例**（`.cursor/commands/add-logs.md`；无 frontmatter；标题下先放 skill `description` 供 `/` 预览）：

```markdown
# 加诊断日志

在关键路径加可区分候选原因的诊断日志并等人回传

你正在执行纪律积木 `add-logs`（由人触发，非擅自改道）。
1. 完整 Read `.ai-discipline/skills/add-logs.md`
2. 严格按该文件执行
3. 完成后回到用户当前任务；若在某条 SOP 中途，回到该阶段
```

**Claude** 同文，并加（`description` 用 skill 一句话，缺省回退 `title`）：

```yaml
---
description: 在关键路径加可区分候选原因的诊断日志并等人回传
disable-model-invocation: true
---
```

**Codex**：`SKILL.md` 正文同义；`description` 同上；侧车/字段关闭隐式调用。

### 10.3 安装器职责（最小）

1. 真源：`seed/**` → `.ai-discipline/**` 时默认 **不覆盖已有** skill/sop/rule/docs（及已有 `commands/index.yaml`），**只补缺**；`--force` 时同名整文件覆盖、不 prune  
2. 读 `commands/index.yaml`；校验 skill 文件存在  
3. 对**用户所选**宿主：**覆盖**生成 command 薄壳；清单外旧薄壳删除  
4. 若选 Cursor：写入/覆盖极薄 always 锚点 `ai-discipline.mdc`（只指向 Read `AGENTS.md`）  
5. 跑或提示 `sync`（index + AGENTS 标记块可重写）  
6. 不把 command 表写入 AGENTS

## 11. 元 skill 写盘 / 校验 / sync（定稿）

**M1：** 元 skill 只改真源；生成物与宿主薄壳由 CLI 负责，不靠模型手改 `workflows/index` / AGENTS 标记块。  
**V1：** 独立 `discipline validate`；`sync` / `install` 亦会跑同一套校验。

### 11.1 分工

| 角色 | 职责 |
| :--- | :--- |
| **`discipline-author`（元 skill）** | 澄清意图 → 变更摘要 → 人确认 → 写 `.ai-discipline` 真源（`*.md` / `commands/index.yaml`） |
| **CLI `discipline validate`** | schema、路径、引用、command 约束；失败非 0 |
| **CLI `discipline sync`** | 先 validate；重写 `workflows/index.md` + AGENTS 标记块（及受管的 `CLAUDE.md`） |
| **CLI `discipline install`** | 先 validate；写所选宿主 command 薄壳（§10）；可与初次落盘真源一并做 |

### 11.2 元 skill 写盘流程

```text
人触发 command：discipline-author
  → 明确对象：rule | skill | sop | command 声明
  → 明确操作：增 | 删 | 改（含 rename）
  → 输出变更摘要（路径、要点、受影响的 steps/inserts/command 数）
  → 等待人明确确认（未确认禁止写盘）
  → 只写真源文件（路径约定见 §5 / §8）
  → 提示并执行（或请人执行）：
       discipline validate
       discipline sync
       # 若本次改动了 commands/index.yaml：
       discipline install --hosts <已选宿主>   # 至少重登记 commands
```

**禁止：** 业务 SOP 中途改纪律；未确认写盘；SOP 内联大段 skill 做法；command 挂 sop；command >10；模型直接改 index/AGENTS 生成区冒充 sync。

**重命名 / 删除：** 摘要中必须列出将断裂的引用；写盘时同步改掉其它 SOP 的 `steps`/`inserts`（或先拒绝并列出校验将失败项）；仍以随后的 `validate` 为准。

### 11.3 `discipline validate`（V1）

| 检查 | 内容 |
| :--- | :--- |
| schema | `kind`/`id`/`name`/`description`；rule 的 `role`/`always`；`always:true` 必有 `summary`；sop 必有 `triggers`/`steps`；`priority` 若存在须为整数 |
| 路径 | 文件名 = `id`；位于约定目录；同 id 不多重文件 |
| 引用 | 每个 `steps[].use` / `inserts[]` 的 skill、rule 文件存在；建议检查 `ask-route` 文件存在 |
| command | `commands/index.yaml`：skill 存在、≤10、含 `discipline-author`、无重复 |
| 残留 | 不得引用已删除 id |

### 11.4 `discipline sync`（M1）

1. 跑 `validate`（失败则中止）  
2. 扫描全部 `kind: sop` → 重写 `.ai-discipline/workflows/index.md`（含 `priority`）  
3. 收集 `always: true` 的 `summary` → 重写仓根 `AGENTS.md` 标记块（总禁令 + 强制加载含 `ask-route`；**不含** command 表）  
4. 若本包管理 `CLAUDE.md`，按既定镜像策略更新  
5. **不**登记宿主 command（那是 `install`）  

人直接改真源（不经元 skill）后，同样应跑 `validate` + `sync`（改了 command 再 `install`）。

### 11.5 CLI 子命令一览（本层约定名）

| 命令 | 作用 |
| :--- | :--- |
| `discipline validate` | 只校验 |
| `discipline sync` | validate + 更新 index / AGENTS 生成区 |
| `discipline install` | validate + 落盘/刷新真源模板（若需要）+ 按宿主写 command 薄壳 + 建议继以 sync |

具体 flag（`--hosts`、`--commands-only` 等）实现期可定，语义须符合 §10 与本节。

## 12. 包内目录树（定稿）

包路径：`03-spec-orchestration/packages/ai-discipline-spec/`。  
CLI 实现放 **`scripts/`**（同现有 mdd 包习惯，非 `src/`）。  
`seed/` 在包内**不加点前缀**；安装映到业务仓 `.ai-discipline/`。

```text
packages/ai-discipline-spec/

  README.md
  DEVELOPMENT.md

  seed/                        # → 业务仓 .ai-discipline/
    workflows/                 # SOP 真源（index.md 可由 sync 生成，seed 可带初始份）
```

### 12.1 映到业务仓

**权威：** 业务仓落盘后以 `.ai-discipline/` 与仓根 AGENTS 为准；包内 `seed/` 是发行默认值。  
**生成物：** `workflows/index.md`、AGENTS 标记块、宿主薄壳 —— 由 CLI 写出，不以手改 seed 冒充已 sync。

### 12.2 `package.json` 约定（要点）

## 13. 非目标

- 不把规格全生命周期引擎、记忆库、多角色编排、宿主做成内核必装。  
- **本层不提供硬拦**（工具拦截 / 提交闸 / CI 门禁 / 步骤状态机）；软纪律 + 锚点保险 + 人工。  
- 不用「一个大 skill」替代薄 SOP；**不把 command 当成 SOP 入口**；不用 SOP 表达「路由未命中」（用 `ask-route`）。  
- 不把整库 skills/rules 镜像进宿主发现路径；再次 install 默认**不覆盖**用户已改真源（只补缺）；显式 `--force` 除外（同名覆盖、不 prune）。  
- 不注册大量 command；不为 rule/sop/`ask-route` 各挂 command。  
- 当前不做长 SOP 状态文件（用 `handoff` + 人工）。  
- 不把元 skill 当成业务 SOP；不允许无确认改写纪律真源。  
- 不修改既有 `mdd-ai-eng-spec`（稳定后弃用策略另案，本文不展开）。  
- 不自建插件 OS。
